# 이슈 라벨 규칙

이 저장소에는 기본 라벨(`enhancement`, `documentation`, `bug` 등)만 있다. 아래 표는 `feature-issue` 스킬이 라벨을 고를 때 쓰는 기준이다.
라벨 이름은 GitHub에 등록된 영문 이름을 그대로 쓰고, 표에는 한글 이름을 병기해 읽기 쉽게 했다.

## 종류 라벨

| 라벨 (GitHub 이름) | 한글 이름 | 용도 | 상태 |
|--------------------|-----------|------|------|
| `enhancement` | 기능 개선 | 새 기능 (기본 적용) | 기본 라벨, 존재 |
| `documentation` | 문서 | 문서 변경 | 기본 라벨, 존재 |
| `bug` | 버그 | 결함 수정 | 기본 라벨, 존재 |

## 스코프 라벨

변경 파일 경로로 정한다. 여러 스코프가 걸리면 모두 붙인다.

| 라벨 (GitHub 이름) | 한글 이름 | 경로 패턴 | 상태 |
|--------------------|-----------|-----------|------|
| `data` | 데이터 | `data/**`, `*.dat`, `make_dummy*.py` | 필요 시 승인 후 생성 |
| `analysis` | 분석 | `analysis/**` | 필요 시 승인 후 생성 |
| `viz` | 시각화 | `dashboard/**`, `viz/**` | 필요 시 승인 후 생성 |
| `docs` | 문서 | `*.md`, `README*` | 기본 라벨 `documentation` 사용 |
| `tooling` | 도구 | `.claude/**` | 존재 (생성 완료) |

## 규칙

- 저장소에 없는 라벨은 이슈 등록 시 붙이지 않는다. 등록 후 사용자에게 생성 승인을 묻는다.
- 라벨 색상과 설명은 생성 승인 시 함께 정한다. 설명은 한글로 쓴다.
- 라벨을 추가하면 이 표도 함께 갱신한다.
